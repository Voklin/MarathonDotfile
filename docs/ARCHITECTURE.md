# ARCHITECTURE — MARATHON Tactical

Архитектура оболочки **MARATHON Tactical**, спроектированная на основе [`MARATHON_TACTICAL_MASTER_PROMPT.md`](../MARATHON_TACTICAL_MASTER_PROMPT.md) для независимой разработки UI на Windows 11 и надёжного исполнения на CachyOS (Hyprland + Quickshell).

---

## 1. Трёхслойная архитектура (`UI / State / Adapters`)

Проект строго разделяет визуальное представление, контракты состояния и платформенные интеграции:

```text
+---------------------------------------------------------------+
|  UI Layer (ui/)                                               |
|  Чистые QtQuick-компоненты, токены, анимации, экраны          |
|  Импорты: только QtQuick / QtQuick.Layouts / QtQuick.Controls |
|  ЗАПРЕЩЕНО: импортировать Quickshell.* или preview/mocks/     |
+------------------------------^--------------------------------+
                               | (свойства, сигналы, команды)
+------------------------------v--------------------------------+
|  State & Contracts                                            |
|  Симметричный контракт данных и команд (без гигантского bus)  |
|  Обязательные поля устойчивости: available, loading, error    |
+------------------------------^--------------------------------+
          | (Windows Preview)             | (CachyOS Live)
+---------v-------------------+ +---------v---------------------+
| preview/mocks/ & scenarios/ | | shell/services/               |
| Локальные детерминированные | | Quickshell, Hyprland IPC,     |
| моки и переключатель сцен   | | PipeWire, UPower, MPRIS, D-Bus|
+-----------------------------+ +-------------------------------+
```

### 1.1. Слой UI (`ui/`)
- Содержит дизайн-токены (`ui/tokens/`), переиспользуемые примитивы и виджеты (`ui/components/`), переходы (`ui/animations/`) и композиции поверхностей (`ui/screens/`).
- Компоненты получают адаптеры или данные через явные свойства (`required property` / dependency injection).
- Не содержит системных команд, вызовов `Process`, Linux-путей и `Quickshell`-модулей.

### 1.2. Слой State / Contracts
- Минимальные, предметно изолированные контракты с единой семантикой для Windows Mock и Linux Live.
- **Запрещено** превращать контракты в единую глобальную шину событий (`event bus`).
- Обязательные контракты системы:
  1. `Workspaces` — список рабочих пространств (`id`, `name`, `active`, `occupied`, `urgent`), команды переключения/перемещения.
  2. `ActiveWindow` — заголовок, класс/идентификатор приложения, состояние fullscreen/floating, безопасная обрезка длинных строк.
  3. `Audio` — громкость (`0.0..1.0`), `muted`, устройство вывода (`sinkName`), команды изменения/переключения.
  4. `Network` — тип/статус подключения, имя сети/интерфейса, доступность сервиса.
  5. `Battery` — наличие батареи (`available`), заряд, статус зарядки/питания, оценка состояния.
  6. `Brightness` — наличие контроллера (`available`), текущий уровень, изменение яркости.
  7. `Notifications` — активные всплывающие уведомления, история, критичность, DND-режим, действия закрытия/очистки.
  8. `Session` — блокировка, выход из сеанса, перезагрузка, выключение, флаг запроса подтверждения; в моках не вызывает ОС.
  9. `Launcher` — список приложений/безопасных команд, фильтрация, запуск выбранного элемента, состояние пустого результата/ошибки.
  10. `Appearance` — параметры отображения текущей сессии (включая `reducedMotion`, масштаб/плотность, политику скрытия панели при fullscreen).
- **Единое правило отказоустойчивости:** каждый контракт обязан явно отражать состояния `available` (подсистема есть/нет), `loading` и `error` / `errorMessage`, чтобы UI показывал предсказуемые fallback-состояния без падений и null-ошибок.

### 1.3. Слой Adapters
- **Windows Mock (`preview/mocks/`, `preview/scenarios/`):**
  - Воспроизводит точные имена свойств, сигналов, перечислений и методов live-адаптеров.
  - Обеспечивает детерминированные сценарии для проверки границ: нормальное состояние, нет сети, отсутствует батарея, длинное имя окна/Unicode, несколько мониторов (эмуляция параметров), высокий масштаб DPI, ошибки сервисов, пустой Launcher, компактный экран `1366x768` и широкий `2560x1440`.
  - Деструктивные команды (`logout`, `reboot`, `poweroff`, `lock`) имитируются локально (уведомление/смена состояния превью).
- **Linux Live (`shell/services/`):**
  - Тонкие адаптеры поверх поддерживаемых версией Quickshell API: `Quickshell.Hyprland`, `Quickshell.Services.Pipewire`, `Mpris`, `Notifications`, `SystemTray`, а также штатные системные интерфейсы (NetworkManager, BlueZ, UPower, контроллер яркости) после подтверждения их доступности на CachyOS.
  - Отсутствие любого внешнего сервиса приводит к `available: false`, а не к падению `shell.qml`.

## 3. Точка входа Quickshell и многомониторность

- Точная структура точки входа (`shell/shell.qml`), способ запуска (`quickshell -p ...`) и поддерживаемые типы (`PanelWindow`, `Variants` по `Quickshell.screens`, `Process`, сервисные синглтоны) должны опираться на **подтверждённую версию Quickshell** на CachyOS (аудит `D1`) и официальную документацию `quickshell.org/docs/`.
- Скрытые поверхности (`Launcher`, `Control Center`, `Notification Center`, `Session Menu`) загружаются лениво (`Loader` / условное создание или `active: false`), не перехватывают клавиатурный фокус после закрытия и не держат активных периодических таймеров в фоне.
- Верхняя панель (`Top HUD`) учитывает политику размещения по мониторам, безопасную область (`exclusiveZone` / эквивалент поддерживаемой версии) и корректное поведение при переключении окон в fullscreen и hotplug мониторов.

## 4. Интеграция с Hyprland и изоляция сессии

1. **Определение формата перед написанием конфигов:** до этапа `D1` формат конфигурации Hyprland (`hyprlang` / `hyprland.conf` или `hyprland.lua`) и синтаксис правил (`windowrule` vs `windowrulev2`) считаются **неподтверждёнными**.
2. **Изолированный профиль:** конфиги проекта хранятся в `hypr/` и подключаются через отдельный профиль/флаг запуска или изолированную опциональную установку, не перезаписывая `~/.config/hypr/`.
3. **Защита дисплейного менеджера и удалённого доступа:**
   - Изменения в `/usr/share/wayland-sessions/` или настройках DM допускаются только после проверки путей на CachyOS и с явным разрешением владельца.
   - Прежняя сессия пользователя остаётся доступной; TTY (`Ctrl+Alt+F2..F6`) и SSH/VNC/RDP не затрагиваются.
4. **Разделение ответственности при сбое:** если Quickshell упал или перезапускается, Hyprland продолжает управлять окнами, горячими клавишами и запуском терминала без потери контроля над системой.

## 5. Производительность, события и безопасность

### 5.1. События вместо polling
- Для Hyprland используются события/IPC-подписки Quickshell, а не периодический вызов `hyprctl` по `Timer`.
- Для аудио, медиа, трея и уведомлений используются реактивные модели и сигналы Quickshell/D-Bus.
- Если для отдельной метрики неизбежен таймер обновления, его интервал делается настраиваемым, а при скрытии виджета таймер останавливается.

### 5.2. Безопасность внешних процессов и `.desktop`
- Внешние утилиты (например, для яркости или системных действий) вызываются с явным массивом аргументов без оболочки `sh -c`.
- Каждая команда должна иметь контроль кода возврата, обработку ошибок и таймаут.
- Разбор `.desktop`-файлов должен корректно обрабатывать поля `Exec` (удаление field codes `%u`, `%U`, `%f`, `%F`, экранирование аргументов) без передачи строки в произвольный `sh -c`.
- Командное меню Launcher допускает только явно описанный белый список безопасных действий.

### 5.3. Владение D-Bus уведомлений
- Перед активацией центра уведомлений `shell/notifications/` проверяется, какой сервис владеет `org.freedesktop.Notifications` в целевой сессии. Нельзя допускать одновременного запуска двух конфликтующих демонов уведомлений (например, `mako`/`dunst`/`swaync` и Quickshell).

## 6. Разделение проверок: Windows vs CachyOS

| Тип проверки | Где выполняется | Что подтверждает |
|---|---|---|
| Синтаксис/типы QML (`qmllint`), отсутствие `Quickshell`-импортов в `ui/` | Windows / Linux | Статическую корректность QML и чистоту слоёв |
| QtQuick Preview + Mock Scenarios (`preview/Main.qml`) + скриншоты | Windows 11 | Визуальную вёрстку, состояния, контраст, `reducedMotion`, адаптивность, контракт UI |
| Конфиг Hyprland, Quickshell live adapters, D-Bus, multi-monitor, lock/session, `install`/`uninstall` | CachyOS (реальный стенд) | Реальную работоспособность shell в Wayland-сессии |

**Правило отчётности:** успешный запуск на Windows **никогда** не считается подтверждением работы на CachyOS. Недоступные на Windows проверки явно помечаются как `NOT RUN — requires CachyOS`.
