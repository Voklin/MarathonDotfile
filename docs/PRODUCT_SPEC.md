# PRODUCT_SPEC — MARATHON Tactical

Единая продуктовая спецификация MVP (версия 1.0), составленная на основе [`MARATHON_TACTICAL_MASTER_PROMPT.md`](../MARATHON_TACTICAL_MASTER_PROMPT.md).

---

## 1. Видение и цель продукта

Создать **самостоятельную, пригодную для повседневной работы графическую оболочку** (desktop shell / rice) для **CachyOS (Arch-based) + Hyprland + Quickshell** в стиле научно-фантастического тактического интерфейса, вдохновлённого визуальным языком Marathon:
- почти чёрные поверхности и редкие контрастные акценты неонового лайма;
- технические подписи, асимметричная композиция, тонкие контуры, панельные разделители и индустриальные маркировки;
- разработка и визуальная проверка основных UI-компонентов на **Windows 11** (через QtQuick Preview и Mock Backend) с последующим подключением живых адаптеров на Linux;
- запуск в виде **отдельной изолированной сессии/профиля** без перезаписи действующей пользовательской конфигурации Hyprland и без риска для удалённого доступа.

### Что НЕ является целью проекта
- Точная копия или включение закрытых ассетов, логотипов, обоев, иконок и шрифтов Bungie без подтверждённой лицензии.
- Копирование чужого кода без соблюдения лицензии.
- Переписывание Hyprland или создание полноценного desktop environment с нуля.
- Разработка собственного фонового IPC-демона (Python/Rust/Node) без доказанной технической необходимости.

## 3. Функциональный объём MVP (версия 1.0)

### 3.1. Hyprland (изолированный профиль)
- Отдельный профиль/конфигурация, выбираемая безопасным способом без перезаписи `~/.config/hypr/`.
- Рабочие пространства и перемещение окон/фокуса между ними.
- Режим плавающего окна (`floating`), перемещение и масштабирование окон.
- Переключение фокуса, закрытие окна, запуск терминала, блокировка экрана.
- Корректная работа fullscreen-приложений, screen sharing (`xdg-desktop-portal-hyprland` и совместимые механизмы), нескольких мониторов (включая hotplug / изменение конфигурации во время сеанса).
- Согласованные тактические анимации окон с возможностью полного отключения (`reducedMotion`).
- Осмысленный набор горячих клавиш без конфликтов с системными сочетаниями, задокументированный в `docs/KEYBINDINGS.md` (создаётся на этапе настройки профиля).

### 3.2. Tactical Top HUD
- Компактная верхняя панель, размещаемая по мониторам согласно явно выбранной политике.
- Отображение рабочих пространств, активного окна, часов/даты, звука, сети, питания (если есть батарея), системного трея.
- Ненавязчивые состояния ошибок/недоступности сервисов, явные состояния `hover` и клавиатурного фокуса.
- Адаптивная ширина и корректное расположение на разных разрешениях и DPI (от экрана ноутбука `1366x768` до `2560x1440+`, масштаб `100%–200%`), устойчивость к длинным названиям окон и Unicode.
- Автоматическое скрытие или минимизация при fullscreen с безопасным возвратом при выходе из fullscreen.

### 3.3. Launcher
- Быстрый запуск установленных `.desktop`-приложений.
- Поиск с клавиатуры, навигация стрелками, подтверждение по `Enter`, гарантированное закрытие по `Escape`.
- Предсказуемое закрытие без зависаний и без удержания перехвата ввода после закрытия.
- Безопасный разбор `.desktop`-файлов без произвольного `shell-eval`.
- Отдельное меню команд только с явно описанными и проверенными безопасными действиями.

### 3.4. Control Center
- Управление громкостью и выбором аудиовывода (при наличии аудиосервиса).
- Регулировка яркости экрана при доступном аппаратном/системном контроллере.
- Состояние сети и Bluetooth (и управление при наличии поддерживаемых сервисов).
- Переключатель режима «Не беспокоить» (DND) и настройки внешнего вида, влияющие на текущий сеанс (включая `reducedMotion`).
- Корректные сообщения «недоступно» при отсутствии контроллеров или сервисов.
- Выполнение действий через штатные системные интерфейсы/утилиты с проверкой ошибок и кодов возврата.

### 3.5. Уведомления, OSD и управление сеансом
- Механизм уведомлений с историей и закрытием (обязательная проверка D-Bus ownership и исключение одновременного запуска двух демонов уведомлений).
- OSD громкости и яркости с быстрым auto-dismiss и отсутствием блокировки пользовательского ввода.
- Меню сеанса (`Lock`, `Logout`, `Reboot`, `Shutdown`) с обязательным подтверждением опасных/деструктивных операций; в Windows Preview опасные действия строго эмулируются без реального выключения системы.
- Экран блокировки на базе Hyprlock (если поддерживается целевой средой) с собственным оформлением и безопасным fallback при недоступности.

### 3.6. Установка, диагностика и восстановление
- Инсталлятор с обязательным режимом `--dry-run` и проверкой зависимостей.
- Резервное копирование **только** тех пользовательских файлов, которых реально касается установка.
- Безопасное обновление и полное удаление (`uninstall`) без потери пользовательских данных.
- Диагностический скрипт `doctor` для проверки среды, сервисов и конфликтов.
- Понятная документация и проверенный способ аварийного возврата в предыдущую сессию (дисплейный менеджер, TTY, обратное переключение).

## 4. Вне рамок MVP (После стабильной v1.0)

Следующие возможности **запрещено** реализовывать до стабилизации версии 1.0 и отдельного решения владельца проекта:
- игровой профиль с динамическими HUD-элементами;
- редактирование тем непосредственно из UI;
- подробные графики CPU/GPU/температуры и исторические метрики;
- динамическая адаптация контента/поведения под конкретное активное приложение;
- расширенные визуальные переходы, сложные шейдеры и тяжёлые эффекты;
- несколько полноценных цветовых палитр;
- сложные интеграции сторонних сервисов.

## 5. Нефункциональные требования и критерии приёмки

1. **Изоляция и сохранность системы:** прежняя сессия пользователя остаётся доступной; SSH, RDP/VNC и сетевые правила не затрагиваются; на удалённом ноутбуке GUI-сессия не перезапускается автоматически.
2. **Отказоустойчивость:** отсутствие батареи, Bluetooth, NetworkManager, PipeWire или падение Quickshell не приводит к падению оболочки и оставляет управление окнами через Hyprland работоспособным.
3. **Экономичность:** минимум polling; таймеры отключаются при скрытии виджетов; потребление CPU/RAM и время старта измеряются на реальном стенде CachyOS (численные SLA до замеров не выдумываются).
4. **Доступность:** высокий контраст, клавиатурная навигация, видимый фокус, корректная локализация/Unicode, режим `reducedMotion`.
5. **Кроссплатформенная проверяемость:** прохождение Windows Preview обязательно для UI, но не заменяет проверку на CachyOS; Linux-проверки на Windows фиксируются как `NOT RUN — requires CachyOS`.

## 6. Дорожная карта (Этапы реализации)

| Этап | Название | Краткий критерий готовности |
|---|---|---|
| `P0` | Проектная документация и статус | Созданы `AGENTS.md` и базовые документы в `docs/`, нет противоречий, в `STATUS.md` указан следующий этап |
| `D1` | Аудит сред | В `docs/ENVIRONMENT_REPORT.md` зафиксированы подтверждённые версии/инструменты и риски без изменения системы |
| `D2` | Каркас проекта и Windows Preview | Windows Preview запускается, минимум 2 мок-сценария, нет Linux-импортов в `ui/`, шаги воспроизводимы |
| `D3` | Независимая сессия Hyprland/Quickshell | Отдельный профиль запускается/закрывается на CachyOS, старая сессия не затронута, кейбинды и откат проверены |
| `D4a` | Tactical HUD | Адаптивная верхняя панель, рабочие пространства, окно, часы, индикаторы, трей на Windows и Linux |
| `D4b` | Launcher | Поиск и запуск `.desktop`-приложений без `shell-eval`, закрытие по `Escape`, корректный фокус ввода |
| `D4c` | Control Center | Реальное управление доступными подсистемами (аудио/яркость/сеть/BT/DND) и честный fallback |
| `D4d` | Notifications / OSD / Session / Lock | D-Bus ownership уведомлений, non-blocking OSD, подтверждения в меню сеанса, lock screen |
| `D5` | Визуальная доводка | Авторские SVG, лицензированные шрифты/обои, соответствие чек-листу макетов и скриншотов со стенда |
| `D6` | Стабилизация | Нет P0/P1, пройдены тесты отказов, multi-monitor/hotplug, fullscreen, перезапуска shell и отката |
| `D7` | Релиз | Проверены `--dry-run`, `install`, `uninstall`, `doctor`, скриншоты, changelog и подготовка первого тега |
